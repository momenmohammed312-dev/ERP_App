## 2. القيمة والسبب التجاري

- **المشكلة التي يحلها:** إنشاء أمر تشغيل للغير اليوم مستحيل من الـ UI (الـ `_submit` يطلب `bomId` غير موجود في مسار `for_others` فينفجر).
- **النتيجة المتوقعة:** اختيار إذن الاستلام برقمه ثم وصفة متوافقة ثم إنشاء الأمر بنجاح.
- **لو اتأجل، ما الضرر:** وحدة تشغيل للغير كلها معطلة.

## 3. المتطلبات (Requirements)

**يجب أن يفعل (Must):**
1. عند اختيار نوع الأمر تشغيل للغير: picker لاختيار إذن الاستلام (بحث برقم الإذن + اسم/هاتف العميل).
2. بعد اختيار الإذن: picker وصفة يعرض الوصفات المتوافقة أولًا + toggle لعرض الكل.
3. نقطة دخول ثانية من صفحة الإذن نفسها بنفس الفورم/المنطق (لا تنفيذان منفصلان).
4. الأمر الناتج يحمل: `bomId` الحقيقي + `finishedProductId` من الوصفة + حقول الإدخال (`inputProductId/Quantity/Color/Size`) + العميل + التسعير.

**لا يجب أن يفعل (Out of scope):**
- ربط الإذن بالأمر في قاعدة البيانات (لا يوجد DAO update للإذن؛ الـ DAO read-only حسب القرار).
- Product Type / Track Inventory (مستبعد صراحة).

**قواعد العمل الدقيقة:**
- الوصفة المتوافقة = وصفة Active فيها سطر خام واحد على الأقل ضمن أصناف الإذن المختار.
- حقول الإدخال تُملأ من رصيد العهدة المختار، لا من مخزون المصنع.

## 4. معايير القبول (Acceptance Criteria)

- [ ] AC1: اختيار تشغيل للغير يُظهر picker الإذن قبل picker الوصفة.
- [ ] AC2: البحث برقم الإذن (CMR-…) يعمل، وكذلك باسم/هاتف العميل.
- [ ] AC3: الوصفات المتوافقة تظهر أولًا، وtoggle يعرض الكل.
- [ ] AC4: إنشاء الأمر ينجح ويحمل `bomId` + حقول الإدخال + العميل.
- [ ] AC5: زر داخل صفحة الإذن يفتح نفس الفورم مملوءًا بالإذن.
- [ ] AC6: سلوك عربي RTL سليم.
- [ ] الحالات الحدية: إذن بلا أصناف · وصفة محذوفة/غير مفعلة · رصيد عهدة صفر.
