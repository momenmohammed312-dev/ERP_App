## 4. السبب الجذري

**السطحي:** الشارة تعرض عدد أيام خاطئاً.

**الجذري — أربعة تعريفات متناقضة لانتهاء الصلاحية داخل ملف واحد:**

`lib/services/license_manager.dart` على `integration/all-agents`:

| # | الموقع | التعريف | فترة سماح |
|---|---|---|---|
| 1 | `:48-52` `License.isExpired` | `now > expiryDate + 7 أيام` | ✅ **7 أيام** |
| 2 | `:54` `License.isValid` | `!isExpired && isSignatureValid` | موروثة من 1 |
| 3 | `:69-72` `License.daysRemaining` | `expiryDate.difference(now).inDays` | ❌ **لا شيء** |
| 4 | `:228` `validateLicense` | `now > expiryDate` | ❌ **لا شيء** |
| 5 | `:382-383` free path | `now > firstRunDate + 36500 يوم` | ❌ لا شيء |

**آلية إنتاج الخطأ بالضبط:**

```
expiryDate = T + 3 ساعات:

:50   effectiveExpiry = T + 7d + 3h  →  now < effectiveExpiry  →  isExpired = false
:70   if (isExpired) return 0;        →  لم تُنفَّذ
:71   (-3h).inDays = 0                →  daysRemaining = 0        ← ⚠️ القسمة الصحيحة تقتطع

:54   isValid = !false && ... = true
        ⇒ isLicenseActive() = true    ⇒  التطبيق مسموح بالكامل

modern_home.dart:726   days <= 5      ⇒  لون برتقالي
modern_home.dart:759   '$days يوم'     ⇒  "0 يوم"
```

**⇐ خلال نافذة الـgrace البالغة 7 أيام تظهر أرقام سالبة أيضاً:** `daysRemaining = -1 … -7`، و`modern_home.dart:726-730` يلوّن السالب **أخضر** (لأن الشرط `isExpired ? red : days <= 5 ? orange : green` لا يغطي السالب) — أي «‎-3 يوم» بالأخضر مع عمل كامل. **وهذا أسوأ من حالة الصفر لأنها تبدو خلل برمجي.**

**علل مساندة متحقق منها:**

| # | العلة | الموقع | الأثر |
|---|---|---|---|
| أ | `final int gracePeriodDays = 7` مُعلَن كحقل **instance** لا `static` ⇒ يُفقد عند `fromJson` | `:32` مقابل `:98-114` | قيمة غير متوقعة بعد إعادة البناء |
| ب | `getCurrentLicense()` **لا يفحص الصلاحية** ⇒ يُرجع كائن الرخصة عند `expiry+8d` | `:458 return license` | الواجهة تعرض «منتهي» بينما الملف ما زال موجوداً |
| ج | `validateLicense` يرفض عند `expiry` بلا سماح ⇒ سلوكان مختلفان لنفس الرخصة | `:228` | عدم اتساق بين التفعيل والتشغيل |
| د | `integrity_checker.dart:206` يستدعي `deactivateLicense()` بعد 3 إخفاقات متتالية ⇒ **يمسح ملف الرخصة** | منطق القفل الذاتي | فقد رخصة عميل مدفوع |

**لماذا لم يمسكه الاختبار الموجود:** لا يوجد أي اختبار يغطي `License.isExpired` أو `daysRemaining` أو `validateLicense`. الاختبارات الوحيدة في هذا المجال هي `test/unit/hardware_id_service_test.dart` و`test/test_hardware_fingerprint.dart` — ولا تمس الانتهاء إطلاقاً.

**هل هو Regression؟** لا — السلوك قديم، لكن **لم يُوثَّق commit مُحدَّد**. `git log -S "gracePeriodDays"` مطلوب عند التنفيذ لتحديد أول ظهور.

### ✅ قرار صاحب المشروع المُطبَّق — opción (أ): **انتهاء صلب بلا سماح**

**المبرر المُصرَّح به:** العميل بلّغ أن العدّاد صار **سالباً بعد اليوم السابع** والتطبيق **واصل العمل** — أي أن نافذة السماح كانت تُبقي التشغيل سبعة أيام بعد الانتهاء.

### 🔧 التعديل الفعلي — `lib/services/license_manager.dart` (14+/7-)

```dart
// قبل — 7 أيام سماح
final int gracePeriodDays = 7;                                    // حُذف
bool get isExpired {
  return now.isAfter(expiryDate.add(Duration(days: 7)));          // حُذف
}

// بعد — انتهاء صلب
bool get isExpired => DateTime.now().isAfter(expiryDate);

// قبل — يعطي سالباً
int get daysRemaining => expiryDate.difference(DateTime.now()).inDays;

// بعد — محصور عند الصفر
int get daysRemaining {
  if (isExpired) return 0;
  final remaining = expiryDate.difference(DateTime.now()).inDays;
  return remaining < 0 ? 0 : remaining;
}
```

**لماذا هذا الجذري لا العرَضي:** لأن `isExpired` هو ما يقود قرار الوصول (`isValid` ← `!isExpired`) ويقود `hasFeature` و`splash`. تصحيح العرض وحده كان سيترك الوصول غير منطقي.

**لماذا لا يوجد تغيير في `validateLicense`:** هو أصلاً بلا سماح (`:228`) ⇒ أصبح متسقاً لأول مرة في عمر الملف.
