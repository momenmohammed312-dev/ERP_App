# نظام التفويض متعدد الوكلاء — MADAR Delegation System

مجلد `MADAR/delegation/` هو المركز التوثيقي المعتمد لإدارة وتوثيق الميزات المعمارية والبرمجية المعقدة التي يتم تطويرها بنظام **التفويض متعدد الوكلاء (Multi-Model Delegation)**.

---

## محتويات المجلد

1. **[`SKILL.md`](./SKILL.md):**
   * وثيقة المهارة وإجراء التشغيل القياسي (SOP).
   * تعريف أسطول الموديلات:
     * **عقول التفكير والمعمارية:** Claude Opus 5.5 / Sonnet 5.5 / Gemini 4 Argon / Gemini Pro.
     * **محرك التنفيذ السريع:** Gemini 3.8 Flash.
   * سلم التحويل التلقائي عند انتهاء الحصة أو الـ Rate Limit.
   * بروتوكول تسليم المهام ومراجعة الـ Diff.

2. **[`_template-delegated-feature.md`](./_template-delegated-feature.md):**
   * القالب الرسمي المعتمد لتوثيق كل ميزة تُبنى بهذا الأسلوب.
   * يوثق بوضوح وبالتفصيل الدقيق:
     * **مين اللي فكّر وفكّر إزاي** (المعمارية، الحالات الحدية، والقيود المحاسبية).
     * **مين اللي نفّذ وتنفّذ إزاي** (الملفات، الدوال، الاختبارات، والتوافق مع قواعد MADAR).
     * **المراجعة والاعتماد** (أوامر `analyze` و `test` والـ Diff).

---

## كيف تبدأ ميزة جديدة بنظام التفويض؟

1. أنشئ نسخة من القالب باسم:
   ```text
   MADAR/delegation/DELEG-FEAT-<رقم>-<slug>.md
   ```
2. يقوم الموديل المعماري (Opus / Sonnet / Argon / Pro) بملء **القسم 3 (محور التفكير والمعمارية)** وصياغة العقد البرمجي.
3. يستلم **Gemini 3.8 Flash** العقد البرمجي وينفذ الكود والاختبارات ويملأ **القسم 4 (محور التنفيذ البرمجي)**.
4. يراجع الموديل المعماري الكود النهائي وتُسجل نتائج الاختبارات في **القسم 5**.
5. يتم الاعتماد والدمج في الفرع الرئيسي لجميع الوكلاء: `integration/all-agents`.
